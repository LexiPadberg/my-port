# Project rules

## Prompt log
- Keep a `PROMPTS.md` file at the root of the project. Create it if it doesn't exist.
- Before you start on any prompt I give you, log it as a time-stamped entry in `PROMPTS.md`.

## Plans
- When I approve a plan, save a copy of it in a `plans/` folder at the root of the project, numbered in order (for example, `plans/01_resume_website.md`).

## Git
- Never commit to `main`. Before you change any code, create a new branch, or confirm we're already on one that isn't `main`.
- Don't commit, push, merge, or open pull requests. I'll do those myself.
- Use underscores, not hyphens, in names you choose (files, folders, branches).

## Project
- React.js, managed with "create react app"
- Keep a `README.md` that explains how to install and run the app. Update it whenever the app changes.
- Don't add packages we don't need.
- Never put API keys, passwords, or other secrets in the code or in any file that gets committed.
- Keep components modular and reusable.
- Separate content and data from presentation where practical.
 
## Design
- I want a modern and sophisticated visual design
- use the same color scheme throughout the entire application: 
    - Warm Ivory: #F5F2EC  primary page background
    - Mist Blue: #DCE4E8  secondary backgrounds and section accents
    - Dusty Blue: #A4B8C6 decorative elements/highlights
    - Steel Blue: #536F85 buttons and links
    - Deep Navy: #293B4A headings and contrast elements
    - Coral: #E07A5F accent "pop", used sparingly for dots, lines, bars, borders, and glows (never for text: too light to read)
- Prevent horizontal scrolling and overlapping content.
- Use dynamic layout sizing rather than fixed-widths.
- Must work on desktop, tablet, and mobile devices
- Proper spacing and alignment
- No broken links or images
- No spelling or grammar errors


## Content
- Use accurate information about my education, experience, projects, and skills.
- Never invent employers, job titles, certifications, project results, or technical experience.
- Ask me for missing information instead of making assumptions.
- do not use advanced technical wording that a non technical recruiter would not understand.
- Use placeholders for contact information until I approve the final content.


## Coding Standards
- Use consistent naming conventions and formatting. This includes descriptive component and variable names.
- Write readable, maintainable code.
- Handle errors appropriately and descriptively.
